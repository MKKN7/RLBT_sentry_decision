# 2027 通信协议与 UL 合法观测接入

核对日期：2026-11-16。依据官方中文版《RoboMaster 2027 机甲大师高校系列赛通信协议》V1.0.0（2026-10-29）。不是依据旧赛季 ROS 消息名推测字段。

## 官方资料与解码范围

- 官方协议页：https://bbs.robomaster.com/wiki/20204847/50179263
- 原件：`data/references/official_rmu_2027_protocol/rmu_2027_protocol_v1.0.0_20261029.pdf`，85页；附件长度3,435,583字节，MD5与官方一致；SHA256见同目录`manifest.json`。
- 页面原始API响应保存在同目录`protocol_page.json`；排版文本为`data/rules_text/rmu_2027_protocol.txt`。
- `rl_bt/referee_protocol.py`只解码上游完成帧校验后的payload，不是串口驱动，不建立连接，不生成CRC，不把报文存在当作当前观测有效。
- 主要事实见`data/rmu_2027_protocol_facts.json`。关键PDF物理页10、12、21已渲染核对表格与位偏移。

## 对原设计的具体修正

|来源|官方内容|actor的使用边界|
|---|---|---|
|0x0001／1Hz|比赛类型、阶段、阶段剩余秒、NTP有效后的时间戳|区分UC与UL 3v3；不能把尚未NTP同步的raw字段直接当采样时钟|
|0x0002／结束事件|0平局、1红胜、2蓝胜|这是全局红蓝，不是己方/敌方编号|
|0x0003／3Hz|己方重装、3/4步兵、哨兵HP，双方设施HP，双方伤害差、控制度|**没有敌方各机器人HP**；无敌、复活进度也不在本包。HP为0还可能是未上场或被罚下，不能仅凭0认定死亡|
|0x0101／1Hz|己方补给区激活；第二个32位字中有UL三个控制区激活及控制状态|能用确认后的owner/activation，不包含精确0..5占点进度；不能把本机RFID等同队伍完全控制|
|0x0201／10Hz|自身HP/上限、性能及供电状态|自身状态可输入；热控火控仍由已有模块执行|
|0x0208／10Hz|17/42mm允许发弹量、金币、堡垒储备|字段存在不等于该赛制允许哨兵购买；UL购买仍关闭|
|0x0209／3Hz|自身检测到的RFID卡|bit0为己方补给；bit11/12/13为UL R高地/B高地/中央；基地卡不是补给卡|
|0x020B／1Hz|服务器发给己方哨兵的己方重装及3/4步兵坐标|与机器人间自定义通信不同；不能凭“禁止多机通信”推断该服务器字段也不存在。**UL实机播发、有效性和坐标配准尚未验证**，默认不能当已校验输入|
|0x0A01、0x0A02|敌位置、敌HP，经雷达无线链路发给雷达|不属于哨兵常规链路；UL不能从仿真真值直接填进对应actor字段|

原多实体表中敌方“血量比、存活、无敌”不能默认全局可得。可使用本机视觉产生的估计、最后观测和缺失标志；数值必须连同来源、样本时间、接收时间、有效性一起进入adapter。它们与真值分开，真实状态可以用于训练环境结算／诊断，不进入actor。

协议将0x0003的控制度称为“累计控制度”，UL手册又描述开局600并递减。解码器保留raw字段名；在接口实测前，不擅自采用`600 - raw`或把它当当前剩余控制度。UL占点模型的精确内部progress也不能冒充1Hz公共报文。

0x020B使用裁判场地坐标，官方说明的原点在红方补给站附近围挡交点。当前UL社区CAD坐标为西南内场原点，两者**尚未注册**。解码结果显式标记`referee_field_frame_unregistered`，不可直接与CAD候选点计算距离。保留槽被丢弃，不把它们猜成工程、哨兵或敌人坐标；(0,0)也不是文档规定的无效哨兵值。

## 运行契约与验证

`decode_payload(command_id, payload, byte_order=...)`要求调用方明确字节序。PDF偏移表未明确payload端序，本模块不依赖宿主native端序；部署前用裁判串口实录核对。支持0x0001、0x0002、0x0003、0x0101、0x0201、0x0208、0x0209、0x020B，旧长度与非本子集命令直接报错，未来版本不能静默套用当前结构。

8项单测覆盖偏移、signed伤害差、UL控制区bit、RFID与基地/补给区别、保留槽、位置有限值、结果红蓝编号、错误长度、禁止雷达包及显式字节序：

另新增`rl_bt/ul_observation.py`，提供逐包白名单投影与有效性缓存。只接受常规链路来源；sample时间必须由上游注册到单调时钟，不能拿receive时间代替。没有sample时间、没有显式age阈值、超龄或从未收到的包不暴露数值；迟到的旧sample不能刷新缓存。8位wire序号仅作metadata，避免把全局序号当作每种命令的时间。0x020B即使到包仍保留mask，直至实测播发和坐标转换得到独立验证。白名单中没有敌HP、根据HP=0臆测的死亡标记、精确capture progress或UL不存在的设施目标。

缓存按局创建，各包独立有效，调用方必须先确认有效的UL game status再执行任务；它尚不实现跨包原子一致性。新增6项测试覆盖超龄/未知sample、迟到与重复、wire序号回绕、字段白名单、位置mask以及profile/source/时钟拒绝，共14项相关测试通过。尚未连接训练或实机；实际播发、完整串口CRC驱动、坐标TF与actor向量化继续由后续接口实现。
