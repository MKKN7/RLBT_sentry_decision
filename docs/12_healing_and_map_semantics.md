# 回血地点与地图语义核对

日期：2026-11-16。本文首先核对用户提供的 UC V1.0.0／2026-10-15，不代表已核验后续修订。后续同日已取得UL正式手册及3v3 STEP，详见`docs/13_rmul_official_rules_review.md`；UL仅激活己方补给区回血，默认25%/s，另有控制度落后加成，不继承UC常量。

## 1. UC 的“基地回血”需要区分具体点位

已重新渲染并目视核验规则 PDF 第74页（印刷73页，§5.3.1），页面位于 `tmp/pdfs/healing_uc_rule_p074.png`。

|位置／方式|回血条件|与候选点的关系|
|---|---|---|
|己方补给区|激活己方补给区增益点，默认每秒10%上限血量；开始4分钟后且脱战为25%，另受后勤系数影响|基地附近明确的补给区域，不能扩成整个基地区|
|前哨站增益点|对应前哨阵地被己方完全控制，且激活该点；速率为当时补给区速率的50%|必须关联阵地控制状态，不能只看距离或到点|
|金币远程回血|脱战时确认购买，6秒后恢复60%上限血量，另受后勤系数影响；期间死亡无效且不退款|不要求回基地；由金币、资格与事务回执约束|
|基地增益点|§5.6.4.2列举50%防御、兑换弹量、解除虚弱|不能仅凭基地增益点激活就产生回血|
|掩体／躲避点|没有据此自动回血的规则|“安全”与“可回血”是不同属性|

同类回血增益取最大值，不把补给与前哨回血直接相加（§5.6.4.1，PDF105）。机器人异常离线、被罚下等状态还需按完整规则处理。没有在当前原型中实现这些正式状态机。

“回基地回血”可以作为对基地附近己方补给区的口头简称。若队伍决定只回基地补给、不使用前哨回血或付费远程回血，应作为队伍策略限制单独记录，不能写成官方规则禁止其他方式。此项偏好正在向用户确认，尚未设置强制限制。

## 2. 现有训练中的 home 是什么

当前 `alpharm_task_prototype_v1` 使用 alphaRM 固定平面地图，`home` 候选来自该地图己方出生区中心。物理回血只发生在原环境的己方出生矩形内，速率8.125 HP／0.1秒；它不是正式UC补给区，也没有正式前哨回血与远程购买。

低血“靠近home”的高斯距离正奖励只是 shaping，不能把它解释成“距离越近就已回血”。本轮新增分项诊断可将它单独计量或去除，物理回血区域仍保持原样。

BT与RL共用这一导航代理，并不使代理成为正式赛场。以往的胜场只适用于简化原型，不能称为UL或UC整场胜率。

## 3. 正式地图接入条件

UC参考STL已复制并做过低坡面统计，但缺少导航坐标注册、各增益区边界、支撑层／净空／通路、交互卡关联等验证。后续取得UL官方规则与CAD，已核对来源并派生名义表面边界；真实导航和RFID坐标尚未注册。没有把参考边界当作已核验的实机点位。

正式候选需要明确：`own_supply_zone`、`own_outpost_buff`、`base_buff`、`safe_cover`等语义；回血资格与当前控制状态、交互激活和裁判反馈关联。路径可达只解决“能否过去”，不代表到点就能获得回血。

结构化语义见 `configs/healing_semantics.json`，其中所有正式导航区域坐标暂留null。这是核对资料，未作为可运行正式环境配置。

## 4. 奖励工程本轮进展

已加入子步奖励分项及整局累计：中心、比分、伤害、击杀、存活、低血靠家、离家、死亡、闲置、开火和终局。接触及数值差明确保留为residual。观测没有新增仿真真值。

已有可选 `upstream/no_home/no_fire/no_home_no_fire/own_damage`。`own_damage`只提高上游本车raw命中奖励权重，不宣称等于实际扣除HP；尚未做这组长训练。新实验用 `--init-from`复用权重，重置optimizer／环境／RNG，明确不称精确续训；评估仍统一使用原奖励和同一物理环境。

只完成128决策的奖励记录smoke与基线一致性核验，不据此报告策略提升。下一轮长训练应先明确正式赛场语义和用户的回血策略限制，不能将代理奖励调优冒称为正式赛事决策完成。
