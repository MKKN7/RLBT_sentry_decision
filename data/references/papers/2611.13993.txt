                                                                                            Abstract
                                                      Reinforcement learning from formal specifications often separates task definition,
                                                      reward shaping, curriculum design, and policy diagnostics into different mathemat-
                                                      ical objects. This fragmentation requires additional conversion steps and discards
                                                      structure already present in the specification, such as subtask boundaries, ordering
                                                      constraints, and quantitative measures. We introduce TBTCL (Temporal Behavior
                                                      Tree Centric Learning), a framework that uses Temporal Behavior Trees (TBTs)
                                                      as a unified interface for specification-guided reinforcement learning. A single
                                                      TBT specifies the task, induces dense robustness-based rewards, defines a cur-
                                                      riculum, and supports better understanding of learned policies. By adapting TBT
                                                      syntax and semantics for specification-guided reinforcement learning, we provide
                                                      a formalism that is more expressive than popular specification languages such as
                                                      LTL and inherently hierarchical. We present algorithms to automatically extract a
                                                      curriculum DAG and derive dense, robustness-based rewards directly from TBT
                                                      semantics. Furthermore, we utilize TBT trace segmentation to build understandable
                                                      competence profiles and automatically adapt the reward toward bottlenecks. We
                                                      evaluate TBTCL on six specifications across discrete and continuous domains
                                                      and show that Temporal Behavior Trees can serve as a specification, a reward, a
                                                      curriculum, and a diagnostic.


                                         1     Introduction
                                         Temporal Logics are a powerful tool in reinforcement learning, enabling the formal specification
                                         of tasks and serving as the engine of Specification-Guided Reinforcement Learning. Most standard
                                         approaches convert a logical specification into a deterministic finite automaton, which is then used to
                                         guide the learning process. While this conversion is necessary to translate standard logics such as
                                         LTL [Pnueli, 1977] into a form suitable for RL, it incurs a high cost as it loses crucial information at
                                         each step. Properties such as subtask boundaries, quantitative performance measures, hierarchical
                                         structures, and task orderings and priorities are already present in the logical specification but are
                                         discarded by most methods during intermediate conversion steps.
                                         The core cause of these problems is that most specification languages are not designed for purposes
                                         beyond task specification. A typical pipeline represents the task specification in one object, derives
                                         a reward in another, constructs a curriculum through an additional procedure and yet another rep-
                                         resentation, and then relies on separate diagnostics and derivations to understand how a learned
                                         policy behaves, performs, and fails. As such, a potential solution would be a specification language
                                         that provides the task definition, a dense reward, a curriculum, and behavioral diagnostics, without
                                         requiring separate conversion algorithms, representations, or user inputs for each. In this paper, we
                                         argue that a single formal object can simultaneously serve as the task definition, a dense reward
                                         source, a curriculum structure, and a diagnostic model.

We show that Temporal Behavior Trees (TBTs) [Schirmer et al., 2024] have these important properties
and provide a flexible formalism for reinforcement learning. Existing work has developed this for-
malism for monitoring and trace analysis of cyber-physical systems [Schirmer et al., 2024, Schirmer,
2025, Schirmer et al., 2026] and has demonstrated its power and flexibility in these applications.
A TBT composes STL formulas at its leaves with tree-level operators such as sequence, parallel
composition, and fallback. The STL leaves provide quantitative robustness, while the tree structure
describes how behaviors compose over a trace. This hierarchical structure, which combines STL
formulas at the leaves with tree-level operators, enables a concise and expressive definition of subtasks
and their interconnections, which are frequently goals in reinforcement learning. This combination
further enables more concise and expressive specifications than those of commonly used logics such
as LTL. Furthermore, the quantitative semantics encoded by a robustness metric for TBT yields a
dense reward signal and builds on previous work in the field that adapted the robustness of logics
such as STL for Reinforcement Learning [Várnai and Dimarogonas, 2020]. Finally, TBTs support
trace decomposition, connecting policy rollouts directly to the specification expressed as a TBT
without additional steps, and can be used to evaluate policy behavior and identify bottlenecks and
weak points.
Building on these properties, we adapt the Temporal Behavior Trees for reinforcement learning
and demonstrate their use in specification, training, and evaluation. We present TBTCL (Temporal
Behavior Tree Centric Learning), a framework that exploits this unified structure. Given a TBT
specification, TBTCL extracts a curriculum represented by a directed acyclic graph (DAG) by
structural recursion over the tree, trains a single policy through a bottom-up sequence of subformula
reward functions, and advances stages based on achieved STL robustness rather than fixed episode
budgets. When learning stalls, trace segmentation can identify the bottleneck subtask and redirect
training to address it. Moreover, the same segmentation algorithm that drives online curriculum
adaptation can also serve as a runtime diagnostic mechanism, decomposing any evaluation trace into
per-subtask quality scores directly aligned with TBT semantics, without requiring any additional
external mechanism.
We make the following contributions:
• We present Temporal Behavior Trees as a unified interface for specification-guided RL, adapting
  the semantics to reinforcement learning (Section 3.1).
• We use the quantitative robustness semantics of TBTs to derive a dense reward from the prefix
  robustness of the TBT (Section 3.2).
• We leverage the tree structure of TBTs and present an algorithm to extract a curriculum directly
  from their structure and semantics (Section 3.3).
• We demonstrate how the TBT trace segmentation mechanism can be used to understand policies
  and improve their learning by identifying bottlenecks during training (Section 3.4).

2     Background
Signal Temporal Logic. Signal Temporal Logic (STL) [Maler and Nickovic, 2004, Donzé and
Maler, 2010] was developed for monitoring and verification of cyber-physical systems.
An STL formula is defined inductively as φ ::= µ | ¬φ | φ1 ∧ φ2 | φ1 ∨ φ2 | ♢[l,u] φ |
□[l,u] φ | φ1 U[l,u] φ2 , where µ : Rn → R is an atomic predicate over the state space and [l, u] are
optional time bounds (omitted ⇒ full signal). ♢ (Eventually) requires satisfaction at some point;
□ (Globally) requires it at all points; U (Until) requires the first operand to hold until the second
becomes true.
It extends Boolean temporal logic to real-valued signals, replacing the binary satisfied/violated verdict
with a quantitative robustness score. The robustness of a given STL formula is a real number whose
sign indicates satisfaction and whose magnitude measures the margin. We provide a full definition of
STL semantics, syntax and recursive robustness computation in Appendix C.

Temporal Behavior Trees. Temporal Behavior Trees (TBTs) [Schirmer et al., 2024] compose STL
leaves with hierarchical operators, yielding a two-level language: tree structure for compositional
organization, STL for quantitative leaf-level properties. A TBT leaf L EAF(φ) evaluates an STL
formula, while a sequence node S EQ(T1 , T2 ), a parallel node PARM (T1 , . . . , Tk ) with quorum M ,
and a fallback node F BACK(T1 , . . . , Tk ) compose child behaviors over trace segments:
             T ::= L EAF(φ) | S EQ(T1 , T2 ) | PARM (T1 , . . . , Tk ) | F BACK(T1 , . . . , Tk ).
Intuitively, S EQ searches for a cut point such that the prefix satisfies the first child and the suffix
satisfies the second. PARM evaluates all children on the same segment and requires at least M
to succeed (quorum). F BACK represents alternatives, selecting the child and suffix with maximal
robustness. We provide a detailed description of the TBT syntax and semantics in Appendix C.

Rollouts as traces. We consider episodic reinforcement learning in a Markov Decision Process
(MDP) with horizon H and initial-state distribution µ0 . A rollout under policy π, starting from
s0 ∼ µ0 , induces a finite trajectory σ = (s0 , . . . , sH ) of environment states, which we call a trace
following the formal methods literature, optionally augmented with real-valued signals such as
distances to goals, hazards, or objects. STL predicates are evaluated on this trace: an atomic predicate
µ maps a state or signal value to a real number, with µ(st ) > 0 indicating that the predicate is
satisfied at time t. We write σ[l:u] to denote the contiguous segment from time l to u.

3     Method
We show that Temporal Behavior Trees can act as the specification and as a dense reward and as a
curriculum and as a diagnostic metric. First, in Section 3.1, we argue that TBTs are an expressive
and succinct specification language for describing complex behaviors and a powerful formalism for
describing reinforcement learning tasks. Afterward, in Section 3.2, we show how STL’s robustness
metrics are inherited by TBTs and present adaptations that enable effective training directly using
TBT semantics. In Section 3.3 we demonstrate how the tree structure of TBTs directly induces a
curriculum schedule, and show theoretical results about it. Finally, in Section 3.4 we use TBTs’
ability to segment traces (in our case, policy rollouts) to both better understand learned policies and
guide the learning process towards better ones.

3.1   Temporal Behavior Trees as Specifications

Temporal Behavior Trees provide an expressive and concise specification language, owing to their
hierarchical structure and expressiveness of the underlying semantics. Temporal Behavior Trees
provide not only a more succinct way to write out many specifications, but are also known to be
more expressive than other commonly used logics. As shown by Schirmer et al. [2024] building on
proofs from Wolper [1983], Temporal Behavior Trees are strictly more expressive than STL, whose
robustness semantics they inherit.
Each leaf of a TBT contains an STL formula describing a simple task, such as reaching a target
or avoiding a hazard. Internal nodes specify how behaviors described by child nodes compose: a

Sequence node (S EQ) imposes temporal order (reach A before reaching B), a parallel node (PARM )
defines simultaneous requirements (reach A while avoiding C), and a Fallback node (FBACK)
represents alternatives (reach either target A or target B). The combination of simple-to-specify leaf
properties with powerful operators enables users to specify hierarchical specifications rather than just
flat, linear-time formulas.
We further adapt the TBT formalism by Schirmer et al. [2024] for reinforcement learning by providing
an operator to describe repeated behaviors, K LEENE(n, Tc ) . This node enables the specification
of n+1 successful repetitions of the child behavior Tc . Its robustness can be computed as the best
partition of the trace into n+1 segments, scored by the weakest repetition:

3.2    Temporal Behavior Trees as Reward Functions

As TBTs inherit the robustness semantics of STL, we can use the dense reward signal to guide learning,
similar to existing work applying STL to RL [Várnai and Dimarogonas, 2020]. A positive robustness
score indicates that a rollout satisfies a TBT specification task, whereas a negative robustness score
indicates a violation of that same specification, with the magnitude yielding a dense margin score.
Using this, we formulate our reward signal as a robustness-based potential over observed prefixes.
For a TBT T , we compute the prefix potential as Φt (T ) = ρ(σ[0:t], T ), with Φt (T ) = 0 when the
prefix is too short to admit a valid decomposition. The dense term for the reward is expressed as the
discounted potential difference.

against the weakest child in the quorum of the PARM node, a step improvement in any child other
than the one currently holding the M -th largest robustness value is masked, and there is no reward
for such improvements [Várnai and Dimarogonas, 2020]. This leads to potentially beneficial policy
changes not being properly rewarded. We combat these issues by adding additional terms adjusting
the reward signal for these situations.

3.3   Temporal Behavior Trees as Curriculum

Owing to their tree structure, we can extract a curriculum directly from a TBT without requiring
additional inputs or representations. As a TBT is a tree, every subtree of a TBT is a TBT as well. We
use this fact and construct a curriculum which iteratively builds up from the leaf nodes of the TBT
toward the full specification. Using this, TBTCL trains a single policy throughout the curriculum,
with progression through the curriculum corresponding to which subtree of the full TBT specification
provides the robustness-based reward.

Curriculum Extraction The curriculum extraction begins with a walk-through of the TBT, defining
the specification task and constructing a Curriculum Graph directly from the semantics of TBTs. We
directly use the hierarchical structure of TBTs, traversing through the tree and building a curriculum
based on the leaf nodes and the internal nodes connecting them.


                                                             6
First, we compute a Curriculum Graph in which each node encodes a stage (the subtrees specification
being learned), and each edge encodes dependencies between stages (which subtask must be mastered
before proceeding to the next stage). We convert a TBT into a Curriculum Graph by traversing it,
with its semantics governing its encoding.
Each L EAF(φ) node is converted into a stage, as it corresponds to learning the behavior encoded in
the STL formula, such as reaching a target or maintaining distance from a hazard. Sequence nodes
S EQ(T1 , T2 ) impose order between stages and encode a dependency between stages such that T1 must
be promoted before the stages extracted from T2 become available. Similarly, F BACK(T1 , . . . , Tk )
encodes a dependency where a single stage becoming P ROMOTED is sufficient to unlock the current
stage.
PAR and K LEENE nodes encode composition stages as they control how rewards from multiple tasks
interact. For PARM (T1 , . . . , Tk ) nodes, every child is first trained as a subobjective, and a joint
stage whose objective is the full parallel node becomes available once at least M child stages are
promoted. For K LEENE(n, Tc ) nodes, the stages of Tc are followed by one stage per repetition count
k = 2, . . . , n+1, each requiring k repetitions of Tc and unlocked by the promotion of its predecessor,
until the full n+1 repetitions are reached.
We show a pseudo-code implementation in Algorithm 2.

Scheduling We convert the Curriculum Graph into a learning schedule by traversing the Curriculum
Graph. The scheduler then moves through one stage at a time, tracking the status of each stage in the
Curriculum Graph following the progression of L OCKED → R EADY → ACTIVE → P ROMOTED.
Stages that have no prerequisites, such as those corresponding to L EAF nodes, start R EADY while all
others start L OCKED. The TBT formula of the stage marked ACTIVE is used as the reward function
as described in Section 3.2.
A stage becomes P ROMOTED after the policy has successfully learned the corresponding subtask,
meaning that over the sliding window of W episodes either the rolling mean robustness ρW or the
success rate ηW is above the respective thresholds (ρW > ρthresh or ηW > ηthresh ). We also
enforce a minimum number of episodes per stage, Emin , before promotion becomes possible.
When all (or, in the case of PARM , at least M ) the dependencies of a stage become P ROMOTED , it
is marked as R EADY and available for selection by the scheduler. The next stage to become ACTIVE
is selected by a scheduler using an on-the-fly topological sort of the Curriculum Graph.
Once all curriculum stages are promoted, they effectively reconstruct the full TBT specification T .
TBTCL then enters a consolidation phase that trains on the full TBT specification, recovering any
degraded subtask performance. This phase is further augmented by the adaptive mode we present in
Section 3.4, which actively recovers policies’ abilities on specific subtasks by directing the reward
towards leaf nodes with the lowest robustness.
We can show that the curriculum that TBTCL builds is a finite, bounded-size DAG (which we discuss
in Appendix D). Furthermore, we can show that the decomposition of the TBT into subtrees, as done
during curriculum generation, aligns with the task described in the full TBT specification. While this
guarantees neither optimality nor convergence, it shows that the tree structure of TBT can be used to
derive a curriculum without requiring external mechanisms or difficulty rankings.
Proposition 2 (Semantic Curriculum Characterization). For any finite TBT specification T and finite
trace σ, ρ(σ, T ) > 0 holds if and only if the operators of T can be resolved recursively into satisfied
leaf-level STL obligations on the corresponding trace segments.

Proof. We use structural induction over the TBT. Leaves directly inherit STL satisfaction and internal
nodes follow TBT robustness semantics. Applying the induction hypothesis gives the corresponding
satisfied leaf obligations in both directions. The full proof is in Appendix D.

ting, often observed in compositional learning, by refocusing the agent on specific tasks that degrade
during the final phase of learning.

4    Experiments
Setup We evaluate TBTCL on six specifications across two domains, spanning reachability,
sequential composition, Kleene repetition, and reach-avoid tasks with safety constraints. We base our
implementation on Stable-Baselines3 [Raffin et al., 2021] and PyTorch [Paszke et al., 2019], with
NumPy [Harris et al., 2020] for the robustness and TBT engines, NetworkX [Hagberg et al., 2008]
for graph operations, and Hydra [Yadan, 2019] for experiment configuration. We ran the evaluations
on a single Dell R6525 (2x AMD Epyc 7773x - 128 Cores, 256 Threads, 2TB RAM).
LetterWorld is a discrete gridworld with lettered target cells; the agent observes its normalized position
in [0, 1]2 and selects from five actions. Manhattan-distance signals serve as inputs to STL predicates;
collisions with obstacles terminate the episode. We use 5 × 5 grids for compositional tasks and a
10 × 10 grid with 14 obstacles for reach-avoid. PointNav is a continuous 2D point-mass domain in
[−5, 5]2 with continuous acceleration in [−1, 1]2 ; waypoints and circular hazards provide Euclidean
distance signals. All methods are trained using PPO [Schulman et al., 2017], 2M environment steps,
20 random seeds and are evaluated over 100 episodes with the stochastic policy.
We evaluate six specifications (Appendix F): single-goal reachability (REACH _ RED, REACH _ A),
sequential composition (RED _ THEN _ BLUE), repetition (PATROL), and reach-avoid (REACH _ AVOID).
We compare TBTCL against five baselines: STL Shaping [Várnai and Dimarogonas, 2020] (dense
robustness reward, no curriculum), AGCL [Shukla et al., 2023] (DFA-based curriculum, Boolean


                                                                  8
reward), SPECTRL [Jothimurugan et al., 2019] (subpolicy decomposition, sparse reward), Sparse
(+1 on task completion) and LDBA [Hahn et al., 2019] (using limit-deterministic Büchi automata to
derive the reward).


Results We report the specification satisfaction rate: the fraction of episodes where the learned
policy produces a trace with positive robustness (ρ > 0). A rate of 1.00 indicates that the policy
reliably produces traces that satisfy the full TBT specification. Table 1 and Figure 5 report satisfaction
rates on the six specifications we evaluate.
All methods can solve single-goal reachability in LetterWorld. The dense robustness reward drives the
sequential and repetition results: TBTCL and STL Shaping both reach 1.00 on RED _ THEN _ BLUE

the sequence (0.95) but not the repetition (0.40), and SPECTRL and Sparse fail. The curriculum
separates methods on reach-avoid tasks: in LetterWorld, TBTCL achieves 0.85 versus 0.74 for
STL Shaping and 0.38 for Sparse; in PointNav, TBTCL reaches 0.64 while STL Shaping, AGCL,
SPECTRL and Sparse remain at 0 and LDBA reaches 0.14. (Figure 5).

5   Related Work
Temporal specifications as rewards and automata. STL robustness has been extensively used as
a dense reward signal for reinforcement learning and control [Aksaray et al., 2016, Balakrishnan and
Deshmukh, 2019, Várnai and Dimarogonas, 2020, Camacho et al., 2019]. Automata-based methods,
such as Reward Machines [Icarte et al., 2018, 2022], LDBAs [Hahn et al., 2019] and AGCL [Shukla
et al., 2023], expose task structure through automaton states and transitions. We build on this line
of work but keep task semantics, reward, curriculum, and diagnostics in a single TBT rather than
deriving separate objects or requiring additional inputs.

Compositional specification languages. SPECTRL [Jothimurugan et al., 2019] and DiRL [Joth-
imurugan et al., 2021] also use logical structure to decompose RL tasks, train subpolicies, and
compose them at execution time. TBTCL instead trains a single policy through changing subfor-
mula rewards, avoiding execution-time policy composition. The TBT semantics also provide trace
segmentation, offering direct evidence for policy diagnostics and adaptive consolidation.

Temporal Behavior Trees. Temporal Behavior Trees were introduced for robust monitoring and
segmentation of cyber-physical traces [Schirmer et al., 2024], and later applied to the analysis of
autonomous systems and trace repair [Schirmer, 2025, Schirmer et al., 2026]. Concurrent work by
Puranic et al. [2026] uses TBTs to shape RL rewards from imperfect demonstrations. Our approach is
complementary, as it does not require demonstrations or trace repair; instead, it uses the TBT directly
to generate curriculum stages, training rewards, and diagnostics.

Hierarchical and curriculum RL. Hierarchical RL decomposes behavior into skills or options [Sut-
ton et al., 1999, Dietterich, 2000, Nachum et al., 2018, Levy et al., 2019], while curriculum learning
orders training problems to improve optimization [Bengio et al., 2009, Narvekar et al., 2020]. TBTCL
is closer to curriculum learning: it decomposes the reward and training schedule, not the deployed
policy, and obtains the hierarchy from the formal specification rather than from learned option
discovery or a task generator [Florensa et al., 2017, Dennis et al., 2020, Jiang et al., 2021].

6   Limitations
We evaluate TBTCL on six specifications across two small domains, aiming to showcase the
potential of this research direction and show that TBTCL matches dense STL shaping on reachability,
sequence, and repetition tasks, and improves over baselines on reach-avoid tasks where curriculum
and bottleneck redirection matter more. While this is sufficient to show that TBTs can drive rewards,
curriculum extraction, and diagnostics within a single RL pipeline, future work should address its
scalability, optimization, and adaptation to realistic applications. The current reward construction
requires additional terms to handle safety properties and parallel operators, as well as introducing
additional hyperparameters. While TBTs provide a dense reward signal, their effective usage requires
additional tuning via these parameters. As noted by Schirmer et al. [2024], robustness and trace
segmentation can become expensive for long traces and partition-searching operators such as S EQ
and K LEENE. While our formal results on curriculum structure guarantee a well-formed schedule,
they provide no guarantees of convergence or optimal curriculum ordering.

7   Conclusion
We presented TBTCL, a framework for using Temporal Behavior Trees as a unified object for
specification-guided reinforcement learning. The central idea is that the same TBT should not only
define the task but also provide the dense reward, the curriculum structure, and the diagnostic model
for learned policies. By adapting TBT robustness to prefix-based rewards, extracting curriculum
stages directly from the tree, and using trace segmentation for bottleneck analysis, TBTCL preserves
the structure that is lost in existing methods, where specifications must be compiled into separate,
dedicated objects for rewards, curricula, and diagnostic tools. TBTCL matches dense STL shaping on
reachability, sequence, and repetition tasks, and improves over baselines on reach-avoid tasks, where
curriculum and bottleneck redirection have greater impact. We show the potential of developing a
flexible specification language not only for task description but also for derivation of several RL
objects at once, providing several benefits at minimal cost.

Proof of Proposition 3 (Curriculum Well-Formedness). As E XTRACT visits every node of the finite
tree, it leads to a finite curriculum graph. During its traversal, it creates one stage per leaf, one joint
stage per PARM node, one gate stage per F BACK node, none for a S EQ node, and the n repetition
stages r2 , . . . , rn+1 per K LEENE(n, ·) node. By construction, this gives the vertex count.
For acyclicity, we observe that every edge runs from a stage that already exists to one created later.
S EQ connects the latest stage of T1 to the sources of T2 , which are created only after T1 has been
processed, while PARM , F BACK and K LEENE connect existing frontiers to the stage created in the
same step. By construction, at each step, newly created edges can only point from existing stages
to stages created in that step. As they can never encode a dependency in the opposite direction, no
directed cycle can exist. The edge bound follows trivially from ED ⊆ VD × VD .

    Algorithm 2: Curriculum DAG Extraction
    Input :TBT T
    Output :Curriculum DAG D = (VD , ED ), its source stages A and its frontier stages F
1  Initialize empty graph D = (VD , ED );
2  Function Extract(T ):
 3      if T = L EAF(φ) then               // single leaf stage, Globally leaves included
 4          Create stage v with formula φ; add v to VD ;
 5          return ({v}, {v});
 6      else if T = S EQ(T1 , T2 ) then                                 // prefix before suffix
 7          (A1 , F1 ) ← Extract(T1 ); (A2 , F2 ) ← Extract(T2 );
 8          Add edges f → v for all f ∈ F1 , v ∈ A2 ;              // T2 ’s sources wait for T1
 9          return (A1 , F2 );
10      else if T = PARM (T1 , . . . , Tk ) then                           // parts then compose
11          (Ai , Fi ) ← Extract(Ti ) for each child Ti ;
12          Create joint stage j with formula S T and quorum M ; add j to VD ;
13          Add edges S f →   j for all f  ∈    i Fi ;
14          return ( i Ai , {j});
15      else if T = K LEENE(n, Tc ) then                            // one lap, then 2, . . . , n+1
16          (Ac , Fc ) ← Extract(Tc ); P ← Fc ;
17          for k ← 2 to n+1 do
18               Create repetition stage rk with formula “k repetitions of Tc ” (rn+1 carries T itself);
                  add rk to VD ;
19               Add edges p → rk for all p ∈ P ; P ← {rk };
20          return (Ac , P );
21      else if T = F BACK(T1 , . . . , Tk ) then                          // any child suffices
22          (Ai , Fi ) ← Extract(Ti ) for each child;
23          Create gate stage g with formula  S T and quorum 1; add g to VD ;
24          Add edges S f →   g for all f  ∈    i Fi ;
25          return ( i Ai , {g});
26 (A, F ) ← Extract(T ); return (D, A, F );

   Input :TBT T , curriculum DAG D = (VD , ED ) with stage formulas Xv and quorums qv ,
            ρthresh , ηthresh , W , Emin
 1 Initialize: source stages ← R EADY ; all others ← L OCKED ;
 2 while training budget not exhausted do
 3      v ← the ACTIVE stage, else the first R EADY stage in topological order, set to ACTIVE;
 4      if no such v then Train one episode on the reward of T ; continue;       // consolidation
